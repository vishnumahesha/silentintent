# SilentIntent Sandbox Handoff

## What this repo is

Working reference implementation of the SilentIntent demo: a confidential
spend authorization console for an AI agent treasury. Frontend, mock
proof model, contract specification, submission docs, and a verification
script all live here.

## What this repo is not

- Not the official team repo. Do not submit this URL as the entry.
- Not production code.
- Not real payment settlement — the treasury debit is UI state gated by
  the proof result, not an on-chain transfer.
- Not a live Midnight mainnet deployment unless a real Compact circuit is
  separately wired in later.

The CSS variables and tokens live in `app/globals.css` — do not skip it.
The Tailwind v4 setup lives in `postcss.config.mjs` plus the `@theme`
block in `globals.css`.

## What not to copy

- `.git/` — the team repo has its own history.
- `node_modules/` — re-install fresh.
- `.next/` — regenerated by `npm run build`.
- `.vercel/` — the team repo links to its own Vercel project.
- `.env`, `.env.local`, anything that looks like a secret.
- Private strategy notes, judge-Q&A drafts, or old prompt transcripts (if
  any are ever added here, they should not be).
- `CLAUDE.md` from this repo — it encodes a sandbox-only auto-push
  protocol that should not run inside the team repo.

## Current app behavior

The demo runs end-to-end without any backend or API keys:

1. App loads with treasury at **$10,000 USDC** and a redacted "Hidden
   Procurement Policy" panel.
2. **Analyze BrightReach Data** → AI extraction reveals
   `campaign_metadata_reuse` and `partner_enrichment`. The proof model
   marks the forbidden-reuse constraint as failing.
3. **Attempt BrightReach Authorization** → Vendor A renders REJECTED with
   a red proof-receipt card in the Public Verifier. Treasury stays at
   $10,000.
4. **Analyze CleanList Pro** → AI extraction shows clean facts; all four
   constraint checks pass.
5. **Authorize CleanList Pro** → AUTHORIZED receipt appears, treasury
   debits to **$7,750**, and the verifier shows the four commitments
   (intent / offer / vendor / authorization).
6. **Reset Demo** → clears all state cleanly.

`Run Full Demo` is gated behind `process.env.NODE_ENV !== 'production'`,
so it appears in `npm run dev` but is hidden in production builds.

## Mock / demo-only parts

- **Proof model** in `lib/mockProof.ts` uses a deterministic
  FNV/imul-based `stableHash` — not cryptographic. It mirrors the
  constraint shape of the intended Compact circuit so UI bindings won't
  change when the real circuit lands.
- **AI extraction** in `components/AIExtractionPanel.tsx` is a static
  chip list per vendor. No model call, no API key.
- **Treasury debit** is a `useState` decrement in `app/page.tsx`.
- **Commitments** are content-derived but not cryptographic.
- **Contract** at `contracts/SilentIntentAuthorization.pseudo.compact.md`
  is a spec / pseudocode artifact, not a compiled Compact contract.

Mock status is shown on-screen in the app footer
(`Mode: Cached AI + mock proof`, `Network: Midnight local · mock proof layer`).

## Files teammates should inspect first

1. `app/page.tsx` — owns the state machine (vendor states, treasury,
   public log, reset key, last debit).
2. `lib/mockProof.ts` — the proof model. Replace the body of
   `generateProof` with the real Compact verifier call when ready; keep
   the `ProofResult` shape.
3. `components/VendorCard.tsx` — vendor UI, chips, analysis, REJECTED /
   AUTHORIZED result states.
4. `components/AIExtractionPanel.tsx` — extraction reveal animation +
   "Agent Cannot See" truth boundary.
5. `components/PublicVerifier.tsx` — proof timeline + selective
   disclosure cards.
6. `components/HeroTreasury.tsx` — DeFi visual anchor; bound to
   `treasuryBalance` and `lastDebit`.
7. `contracts/SilentIntentAuthorization.pseudo.compact.md` — the
   circuit spec to hand to the Compact author.
8. `scripts/verify-demo-model.mjs` — run with `npm run verify:demo` to
   confirm reject/authorize outcomes and commitment determinism.

## Things teammates will probably want to change

- Update the demo vendor data once a real procurement policy is decided
  on (centralize in a `lib/demoData.ts` if it spreads).
- Replace `generateProof` with the live Compact call; keep the same
  return type so the UI doesn't change.
- Decide whether the public verifier should disclose the policy ID or
  just the policy commitment (currently shows both).
- Decide retention behavior for the public verifier log (currently
  client-only state, cleared on Reset Demo and page reload).
